シミュレーション実行手順書

この手順書では、リポジトリ constrained-optimal-sampling の MATLAB シミュレーションを動かし、 結果を確認して技術報告書・説明資料へ反映するまでの操作を説明します。

対象: MATLAB で評価を実行する担当者 所要時間: 動作確認 約5分／本計算 約35分 更新日: 2026/10/10
01

Overview

目的と対象

このシミュレーションは、wafer 高次補正（HOWA をモチーフにした 3〜5 次の多項式補正）で使うアライメント計測 shot を、 実務制約（象限・半径領域・scan 方向・強制計測 shot・partial shot 除外）を満たしたうえで D 最適／I 最適に選び、 Random・Poisson Disk・Human（ルールベース）などの選び方と、1000 枚の模擬 wafer での補正残差を比べるものです。 評価条件を変えて計算し直したいとき、または計算結果を報告書へ反映したいときにこの手順を使います。

Audience

対象者

MATLAB のコマンドウィンドウにコマンドを入力し、設定ファイル（JSON）を書き換えられる人。プログラムを書く必要はありません。

Scope

対象範囲

評価条件の設定、計算の実行（run_study）、結果の確認、報告書 report/technical_report.tex と説明資料の更新。

Goal

完了条件

結果フォルダに CSV・図・実行記録がそろい、必要な場合は報告書の表と図、本文の数値が新しい結果に合っている状態。

02

Prerequisites

作業前の確認

  • MATLAB R2020b 以降が使える（R2022b で確認済み）。Toolbox は不要です。Parallel Computing Toolbox があれば並列計算もできます（なくても結果は同じ）。
  • リポジトリ一式が手元にある（run_study.m と config/・src/ フォルダが同じ場所にある）。
  • 空き容量が結果フォルダ1つあたり約 250 MB ある（本計算で約 210 MB。うち study_results.mat が約 130 MB）。
  • 本計算の約 35 分のあいだ、パソコンをスリープさせずに置いておける。
  • 報告書を更新する場合は Python 3 が使える（追加のライブラリは不要）。PDF を作るには Overleaf か LuaLaTeX を使います。
  • 説明資料（PowerPoint）を作り直す場合は Node.js と pptxgenjs、Python の python-pptx が使える。
  • 認証情報や環境変数の設定は不要です。
!

作業前の注意

config/default_config.json のまま本計算をすると、Git に登録済みの results/ が上書きされます。 試しの計算は、5章の手順で保存先（study.output_dir）を別のフォルダにした設定ファイルで行ってください。

このリポジトリの数値はすべて乱数で作った模擬データです。実際の Human 配置や実工程の値を入れる場合、それは社内情報です。 その設定ファイルや結果を Git に登録したり、Overleaf などの外部サービスへアップロードしたりしないでください。

04

Smoke Test

動作確認

本計算の前に、プログラムが正しく動くかを短い計算で確かめます。

  1. MATLAB を起動し、リポジトリのフォルダへ移動する

    コマンドウィンドウで cd を実行するか、「現在のフォルダー」でリポジトリのフォルダを開きます。 以下のパスは例です。実際に置いた場所に読み替えてください。 

    cd('C:\work\constrained-optimal-sampling')      % Windows の例
cd('~/work/constrained-optimal-sampling')       % macOS の例

    「現在のフォルダー」に run_study.m が見えていれば正しい場所です。

  2. 自動テストを実行する（約1分） 
    run_tests

    15 件のテスト結果の表のあとに 合格 15 / 15 と表示されれば成功です。 途中で作る results_test/ フォルダは Git の対象外です。

  3. 小規模な計算を実行する（約4分） 
    run_study('config/smoke_config.json')

    [日時] 開始: smoke_test から進み具合が順に表示され、最後に 完了: 合計 ○○ 秒。結果は …/results_smoke と出れば成功です。 結果は results_smoke/ に保存されます（Git の対象外）。時間の大半は図の作成です。

✓

操作のポイント

小規模計算は wafer 40 枚・HOWA 3 次と 5 次だけ・最適化の初期解 3 回で計算するため、数値に意味はありません。 エラーなく最後まで進むかだけを確認してください。

05

Configuration

評価条件の設定

評価条件はすべて config/default_config.json に書かれています（プログラムに数値は埋め込まれていません）。 このファイルは報告書の結果を作った条件なので直接は書き換えず、変えたい項目だけを書いた自分用の設定ファイルを作ります。 自分用の設定ファイルは、先に default_config.json を読み込み、書いた項目だけを上書きします。

  1. config フォルダに自分用の設定ファイルを作る

    例として config/my_study.json を作り、次の内容を貼り付けます。 output_dir は results 以外の名前にしてください。 

    {
  "_about": "自分用の検討設定。default_config.json を読み込み、ここに書いた項目だけを上書きする。",
  "base_config": "default_config.json",
  "study": {"name": "my_study", "output_dir": "results_my_study"},
  "mark_noise": {"levels": {"low": [0.25, 0.25], "nominal": [0.8, 0.8], "high": [1.5, 1.5]}}
}

    この例は、mark 計測誤差（1σ）の nominal を 0.8 nm、high を 1.5 nm に変えた条件です。

  2. 変えたい項目を書き足す

    よく変える項目は下の表のとおりです。各項目の詳しい説明は default_config.json の _note に書かれています。

  3. 設定ファイルを読み込めるか確かめる 
    setup_paths;
cfg = load_config('config/my_study.json');
cfg.study.output_dir

    'results_my_study' と表示されれば読み込めています。 書き方に誤りがあると、どの項目をどう直せばよいかがエラーメッセージに表示されます。

上書きのきまり

{ } で囲んだ項目は、書いた中身だけが上書きされます。[ ] で囲んだ一覧（howa.orders、conditions など）は、一覧ごと置き換わります。

HOWA の次数を変えたら soft_constraint_study.howa_orders と appendix.howa_order も、選んだ次数の中から選んでください。 計測 shot 数の範囲を変えたら figures.map_n_shots・figures.reference_n_shots・appendix.n_shots も範囲内の shot 数にしてください。 書き方の見本は config/smoke_config.json です。

強制計測 shot・Human 配置を shot ID で指定する

shot ID は、一度計算した結果の csv/shot_candidates.csv で確認できます（is_candidate が 1 の行が候補 shot）。 強制計測 shot は mandatory.shot_ids に ID を並べます（空欄のときは positions_mm の座標に最も近い候補 shot を使います）。 

"mandatory": {"shot_ids": [18, 51, 54, 57, 90]}

Human 配置を実際の配置にするには、列 n_shots, shot_id の CSV を作り、そのパスを human.csv_path に書きます。 CSV に書いた shot 数ではその配置を使い、それ以外の shot 数はルールベースのままです。次の例は 5 shot のときに中心と十字の 5 shot を使う指定です。

06

Full Run

本計算の実行

  1. 使う設定ファイルを指定して実行する 
    run_study('config/my_study.json')            % 自分用の設定（results_my_study/ に保存）
run_study('config/default_config.json')      % 報告書と同じ条件（results/ を上書き）

    報告書の結果を作り直すときだけ、2行目の default_config.json を使います。

  2. 終わるまで待つ（既定の条件で約35分）

    進み具合はコマンドウィンドウと結果フォルダの logs/run_log.txt に表示されます。 2026/10/04 の本計算（R2022b、並列化なし）の内訳は、設計 12.9 分、Monte Carlo 評価 4.6 分、統計 2.4 分、soft 制約の補助評価 9.7 分、図 3.4 分でした。

  3. 完了の表示を確かめる

    完了: 合計 ○○ 秒。結果は … と表示されれば終了です。結果の見方は7章を参照してください。

時間を短くしたいとき

方法やり方影響
図を作らないrun_study('config/my_study.json', 'MakeFigures', false)約3分短くなる。図は後から作れる（7章）
soft 制約の補助評価を省く設定に "soft_constraint_study": {"enabled": false}約10分短くなる。報告書の表は作れなくなる

i

途中で止めたいとき

コマンドウィンドウで Ctrl + C を押すと止まります。途中からの再開はできないため、もう一度最初から実行してください。 同じ設定・同じ乱数の種なら、何度実行しても同じ結果になります。

結果の確認

結果は設定ファイルの output_dir のフォルダ（既定は results/）に保存されます。主なファイルは次のとおりです。

logs/timing_log.csv段階ごとの計算時間（秒）

csv/paired_comparison.csv提案法と比較法の wafer ごとの差（改善率・信頼区間・勝率）
csv/shot_reduction.csv基準の手法と同じ残差に必要な最小 shot 数と削減率
csv/selected_shots.csv各手法・次数・shot 数で選ばれた shot

図だけを作り直す

保存済みの結果（study_results.mat）から図だけを作り直せます。MATLAB を起動し直した直後は、先に setup_paths を実行します。

setup_paths;
make_figures('results_my_study');
make_appendix_figures('results_my_study');

最適化の初期解の数が足りているか確かめる（任意・約3分）

addpath('tools');
check_multistart('config/my_study.json');

初期解 20 / 100 / 200 / 400 回の結果を比べた表が表示され、結果フォルダの csv/multistart_check.csv に保存されます。値が 1 に近いほど、回数を増やしても改善しないことを表します。

08

Report

報告書と説明資料の更新

報告書の tex は report/technical_report.tex の1ファイルだけです。 tex の中で % <自動生成 名前> と % </自動生成 名前> の印で囲んだ部分（表 10 個と参考文献リスト）はスクリプトが書き換えるので、手で編集しないでください。 それ以外の本文は手で編集します。

  1. 報告書で使う図をコピーする（MATLAB）

    report/figures/ にある図と同じ名前の図を、結果フォルダから上書きコピーします。

    resultDir = 'results';                          % 本計算の結果フォルダ
reportFigures = dir(fullfile('report', 'figures', '*.png'));
for k = 1:numel(reportFigures)
    name = reportFigures(k).name;
    source = fullfile(resultDir, 'figures', name);
    if ~isfile(source)
        source = fullfile(resultDir, 'figures', 'appendix', name);
    end
    copyfile(source, fullfile('report', 'figures', name));
end
fprintf('%d 個の図をコピーしました\n', numel(reportFigures));
  2. 報告書の表を更新する（ターミナル）

    リポジトリのフォルダでターミナル（Windows はコマンドプロンプト）を開いて実行します。Windows では python3 の代わりに py を使います。

    python3 tools/make_report_tables.py

    最後に technical_report.tex の表 10 個を確認し、○ 個を書き換えました と表示されます。書き換えた表の名前も表示されます。

  3. 本文中の数値を確かめて直す

    本文の文章と、印の外にある表（評価条件の表、代表 wafer の表など）は自動では変わりません。 手順2で画面に出た % 要約 の行と results/csv を見ながら、本文の数値と結論の向きが新しい結果に合っているかを確かめて直します。

  4. 参考文献を変えた場合は参考文献リストを更新する 
    python3 tools/make_bibliography.py

    正本は references/references.json です。並び順は本文で最初に引用された順になります。

  5. PDF を作る

    Overleaf では report/ フォルダ（technical_report.tex と figures/）をアップロードし、メニューの Compiler を LuaLaTeX にしてコンパイルします。 手元に LuaLaTeX がある場合は、report フォルダで次を実行します。 

    latexmk -lualatex technical_report.tex
  6. 説明資料（PowerPoint）を作り直す

    docs/results-briefing_src/README.md の手順に従います。数値は results/csv から自動で取り出されますが、 結論の向きが変わっていないかはスライドを見て確認してください。

!

報告書の表を更新できる結果

make_report_tables.py は、既定と同じ評価条件（HOWA 3〜5 次、7 条件、shot 数 19 まで、soft 制約の補助評価あり）の結果を前提にしています。 ほかの結果フォルダを使うときは python3 tools/make_report_tables.py results_my_study のようにフォルダ名を付けますが、 条件が足りないとエラーで止まるか、表に -- が入ります。

Overleaf は外部サービスです。模擬データ以外の値を含む報告書はアップロードしないでください。

Troubleshooting

困ったとき

「関数または変数 'run_study' が認識されません」と出る

MATLAB の「現在のフォルダー」がリポジトリのフォルダになっていません。4章の手順1で移動してから実行し直してください。make_figures などで同じ表示が出る場合は、先に setup_paths を実行します。

「設定ファイルが見つかりません」と出る

指定したパスにファイルがありません。'config/my_study.json' のようにリポジトリのフォルダからのパスで書くか、フルパスで指定してください。ファイル名のつづりと拡張子 .json も確かめてください。

設定ファイルを読み込むとエラーになる

JSON の書き方の誤りが多い原因です。最後の項目の後ろに , を付けていないか、" や括弧を閉じ忘れていないかを確かめてください。

値の誤りの場合は「constraints.radial.names の数（2）を領域数（境界数+1 = 3）に合わせてください。」のように、直す項目と直し方が表示されます。

Human 配置の CSV でエラーになる

列名が n_shots, shot_id になっているか、shot_id が候補 shot（shot_candidates.csv の is_candidate が 1）か、同じ n_shots の行数がその shot 数と同じかを確かめてください。エラーメッセージに該当する shot_id と shot 数が表示されます。

誤って results/ を上書きしてしまった

Git に登録済みの CSV・実行記録は、リポジトリのフォルダで次を実行すると登録時の状態に戻せます。results/figures/ と study_results.mat は Git の対象外なので戻せません。必要なら default_config.json で本計算をやり直してください（同じ結果になります）。

git restore results
報告書の表に「rank不足」や「--」が入る

「rank不足」は、その shot 数では HOWA の係数を推定できる配置が作れなかったことを表し、強制計測 shot ありで shot 数が少ない場合に起こります。異常ではありません。「--」はその条件の結果がないことを表します。既定と違う条件の結果フォルダを使っていないか確かめてください。

表の更新スクリプトが「印の組が1つだけ必要です」と止まる

technical_report.tex の % <自動生成 名前> または % </自動生成 名前> の行が消えたか、重複しています。git diff report/technical_report.tex で消した行を確かめて元に戻してください。

図のフォントが Arial にならない

macOS の MATLAB では、図のフォントがほかのフォントに置き換わることがあります。数値や結果には影響しません。

i

解決しない場合

エラーメッセージの全文、使った設定ファイル、結果フォルダの logs/run_log.txt を控えて、このリポジトリの管理者に相談してください。設定の詳しい説明は README.md と報告書の「評価方法」の章にあります。
